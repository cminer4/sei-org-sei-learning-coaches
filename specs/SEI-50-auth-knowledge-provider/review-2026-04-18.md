## What is working well

- **Clear separation of concerns**: Knowledge access is centralized in `lib/knowledge/`, and the health route does not import Supabase directly. That matches the goal of swapping data sources later without rewriting every screen.

## Concerns (should address)

1. **Azure stub returns HTTP 500 from the health API**  
   When `KNOWLEDGE_PROVIDER=azure`, the provider throws as specified, but the route catches and responds with **500**. Some teams prefer **501 Not Implemented** so monitoring does not treat it as a server failure.  
   **Impact**: Alerts or dashboards might count these as errors.  
   **Fix**: Return 501 with the same JSON body, or document that 500 is intentional for this endpoint. **Time**: ~15 minutes.

2. **Production `AUTH_SECRET`**  
   If `AUTH_SECRET` is missing in production, Auth.js can fail at runtime.  
   **Impact**: Users cannot sign in; possible 500s on auth routes.  
   **Fix**: Enforce in CI or Vercel (required env). **Time**: ~30 minutes once you add a deploy checklist.
