## What is working well

- **Clear split between “human login” and “ElevenLabs service key”** — Consultants use normal sign-in for most APIs; the voice vendor calls a separate URL with a shared secret. That matches how real products separate people from machines and reduces the chance of mixing the two.
- **Defense in depth on protected APIs** — Middleware blocks anonymous traffic to Assessment routes, and handlers also check the session. If one layer misconfigured, the other still helps.
- **Bearer token check uses timing-safe comparison** — Reduces a class of attacks where someone could guess the key bit by bit. Good practice for service-to-service secrets.
- **Learning summary enforces allowed confidence labels** — Stops the AI from returning random labels that would break the product contract (`Building` / `Developing` / `Strong`).
- **Knowledge retrieval goes through `getKnowledgeProvider()`** — Keeps the door open to swap data sources later without rewriting coaching (matches the business goal of not being locked into one vendor).
- **Prisma schema and a committed migration** — Database changes are versioned, which is what you want before production and teamwork.
- **Build and lint pass** (when required env vars are set for build) — Lowers the risk of shipping broken TypeScript or broken imports.

## Security check

**What looks solid**

- No `STUB_USER_ID` in application code paths reviewed.
- Session APIs use `requireAuth()`; Custom LLM uses a server-only env secret.
- Secrets documented in `.env.example` (good for onboarding developers without leaking values).

**Concerns (explain in plain English)**

1. **`getLatestSessionContext()` uses the latest row in `voice_sessions`**  
   **Risk**: In a busy or multi-user environment, the “latest” row might belong to another session. The voice pipeline could then use the wrong name, company, or agent context — confusing for the learner and hard to debug. **Same pattern existed in the reference app**, but it is still a **data-mixing risk** as usage grows.  
   **Mitigation direction**: Tie stored context to a stable id (session or user) passed through ElevenLabs and back on each Custom LLM request, instead of “latest row wins.” **Effort**: Half a day to a day depending on ElevenLabs wiring.

2. **Raw SQL for vector search (`$queryRawUnsafe`)**  
   **Risk**: If future edits concatenate user input into the SQL string, that could open injection. Today parameters are mostly bound; still worth treating this file as “security-sensitive” in code review.  
   **Mitigation**: Keep all user-facing filters parameterized; consider Prisma’s tagged template API later for extra safety. **Effort**: Ongoing discipline; optional refactor later.

3. **Middleware + handler both enforce auth**  
   **Good**: Reduces accidents. **Watch**: Keep matchers in sync when adding new `/api/*` routes so nothing is accidentally public.
