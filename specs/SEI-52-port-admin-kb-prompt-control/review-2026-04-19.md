## Executive summary (for leadership)

This branch adds an **internal operator console** so your team can manage the knowledge base, edit coach prompts in the database, view system events, and test search quality **without touching the database by hand**. Access is **locked behind company sign-in**, with an optional **email allowlist** for production-style control.

Overall the implementation matches the spec and is **appropriate to merge for an internal pilot**, with a few **follow-ups** on automated testing and scaling the document list as the library grows.

---

## What is working well

- **Two layers of protection**: Middleware stops anonymous users early; each admin API calls `requireAdmin()` (which uses `auth()`), so a misconfigured edge case is less likely to expose data.
- **Clear pilot default**: If `ADMIN_EMAILS` is not set, any signed-in employee can use admin, which keeps demos and early adoption simple. README explains when to tighten this.
- **Architecture alignment**: Admin retrieval goes through `retrieveRelevantContext` and the shared knowledge provider, so operators see what learners get (same search contract as the app).
- **Import safety**: File uploads are capped at **10 MB** with a **30 second** processing budget and **408** on timeout, matching the spec.
- **Operator UX**: Tabs and flows are ported from the proven reference app; the admin surface is consistent with the rest of the product styling (plum palette, clear labels).
- **Destructive actions**: Document delete and import log to `logSystemEvent` where configured, supporting audit trails.

## Test coverage

**Covered today**

- **Allowlist parsing and matching** (case-insensitive, empty list permissive).
- **Import size cap** (10 MB constant and helper).
- Existing **Custom LLM auth** tests unchanged.

**Gaps**

- **No automated HTTP tests** for “admin API returns **401** without session” or “**403** when `ADMIN_EMAILS` is set and user is not listed” (spec FR-007 / SC-004). Those behaviors are implemented in middleware and `requireAdmin`, but **regressions would not be caught by CI** without integration or route-level tests.
- **No automated test** that import exceeds 30 seconds returns **408** (would need a controlled slow mock).

**Recommendation**: Add a small follow-up ticket for route-level or integration tests for admin auth, or document manual QA checklist for each release until then.

## Security (business risk)

- **Strengths**: Admin routes are not public; optional email allowlist reduces risk if the app is opened to a broader Entra tenant. Secrets stay in environment variables; `ADMIN_EMAILS` is not shipped to the browser as a dedicated bundle string (still server env).
- **Session email**: If `ADMIN_EMAILS` is set and the identity provider does not return a stable email claim, legitimate users could be blocked. **Mitigation**: Confirm Entra profile includes email in staging before production allowlisting.
- **Permissive default**: With an empty allowlist, **any** signed-in tenant user could open admin. **Mitigation**: README already calls this out; set `ADMIN_EMAILS` before broad rollout.
- **Error responses**: Most API errors return generic messages; good for production. Console logging may still contain detail in server logs (normal).

---

## Performance (user experience)

- **Document list**: The API loads all matching documents in one query (same pattern as reference). Fine for **hundreds** of docs; if the library grows into **thousands**, operators may notice slower loads. **Suggestion**: Pagination or a higher default filter later (not a blocker for pilot).
- **Import**: Large files within the 10 MB cap can still take most of the 30 second budget when embedding; that is expected and bounded by design.
